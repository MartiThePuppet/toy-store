# Игрушечная — магазин игрушек

Клиентская часть интернет-ресурса «Магазин игрушек», разработанная в рамках курсовой работы. Реализация использует HTML5, CSS3 и JavaScript без фреймворков, npm-пакетов и этапа сборки.

Проект представляет собой учебный прототип: серверная регистрация заказов, платежи, складской учёт и отправка писем не реализованы. Цены, наличие, характеристики и контактные сведения — макетное наполнение. При проверке формы используйте вымышленные контактные и адресные данные.

## Быстрый запуск

### Windows PowerShell

Откройте терминал в папке `Сайт` и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Server.ps1
```

Откройте **http://localhost:8080/**. Для остановки сервера нажмите `Ctrl+C` в терминале.

Если порт занят, выберите другой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Server.ps1 -Port 8090
```

В этом случае адрес сайта — **http://localhost:8090/**.

Сервер предоставляет только статические HTML, CSS, JS и SVG-файлы. Он слушает `localhost`, принимает GET/HEAD и не обрабатывает форму заказа. Это инструмент локального просмотра, а не серверная часть магазина и не средство публичного размещения. Телефон не сможет открыть сайт компьютера по своему адресу `localhost`.

### Visual Studio Code и Live Server

1. Откройте папку `Сайт` в Visual Studio Code.
2. Установите расширение **Live Server**.
3. Откройте `index.html` командой **Open with Live Server**.

Установка зависимостей и сборка не требуются.

Не используйте открытие HTML двойным щелчком как основной способ проверки: поведение `localStorage` для `file://` не гарантируется. Запускайте проект по HTTP.

## Страницы

| Файл | Содержание |
| --- | --- |
| `index.html` | Главная: основной блок, пять категорий и подборка товаров |
| `catalog.html` | Каталог с поиском, фильтрами и сортировкой |
| `product.html` | Общий шаблон подробной страницы товара по параметру `id` |
| `cart.html` | Корзина, изменение количества, удаление и итог |
| `checkout.html` | Контактная форма, способ получения, адрес и результат оформления |
| `delivery.html` | Сведения о способах получения и расчёте стоимости |
| `contacts.html` | Контактный раздел; дополнительные сведения находятся в общем подвале |

Содержимое страниц и общие шапка и подвал формируются JavaScript. HTML-файлы содержат оболочку документа, подключения ресурсов и сообщение `noscript`. При отключённом JavaScript каталог и корзина недоступны.

## Возможности

### Ассортимент и каталог

- 22 товара в пяти категориях: конструкторы, мягкие игрушки, настольные игры, транспорт и творчество.
- Поиск по подстроке названия без учёта регистра.
- Совместные фильтры по цене, категории, возрасту ребёнка и наличию.
- Проверка диапазона: цена «от» не должна превышать цену «до».
- Сортировка по цене, названию и исходному порядку набора данных.
- Число найденных товаров, сброс условий и отдельное состояние пустой выдачи.
- Состояние отбора отражается в URL без перезагрузки страницы.

Возрастной фильтр использует правило `product.minAge <= age`. Например, для ребёнка трёх лет выбираются позиции с минимальной маркировкой 0+, 1+, 2+ и 3+. Это правило отбора, а не индивидуальная рекомендация по выбору игрушки.

Примеры адресов:

```text
catalog.html?q=город
catalog.html?category=creative
catalog.html?category=creative&min=800&max=1500&stock=1&sort=price-asc
product.html?id=city
```

Параметры каталога: `q`, `category`, `age`, `min`, `max`, `stock=1`, `sort`. Допустимые значения сортировки: `default`, `price-asc`, `price-desc`, `name`.

### Товары и корзина

- Единый шаблон подробной страницы с описанием, характеристиками и связанными товарами.
- Обработка неизвестного или отсутствующего `id`.
- Запрет добавления товара с `inStock: false`.
- Добавление с суммированием количества существующей позиции.
- На карточках главной и каталога после добавления отображается контрол `− количество +`.
- Ограничение количества одной позиции: от 1 до 20. Это ограничение прототипа, а не реальный складской остаток.
- В корзине доступны кнопки количества, ручной ввод, удаление позиции и полная очистка с подтверждением.
- Стоимость товаров рассчитывается как сумма `price × qty`; счётчик шапки показывает суммарное количество единиц, а не число разных позиций.
- Счётчик около иконки корзины скрыт, если она пуста.
- Состав корзины восстанавливается из хранилища с проверкой записей.
- Изменения корзины в другой вкладке обрабатываются событием `storage`.

### Оформление

При пустой корзине форма недоступна: выводится ссылка на каталог.

Проверяются:

- имя — не менее двух символов после удаления крайних пробелов;
- email — заполнение и формат средствами поля `type="email"`;
- телефон — допустимые символы и от 10 до 15 цифр.

Способы получения:

- **самовывоз:** 0 ₽; адресная группа скрыта и отключена;
- **доставка:** 300 ₽; появляются отдельные поля города, района, улицы, дома и квартиры.

Район необязателен. Для доставки обязательны город, улица, дом и квартира. Флажок **«Частный дом»** отключает и приглушает квартиру, снимая требование её заполнения. При возврате к обычному адресу поле снова становится обязательным.

После успешной проверки выводятся условный номер, состав и итог, форма сбрасывается и корзина очищается. Номер создаётся в браузере на основе времени, не проверяется сервером и не подтверждает реальную регистрацию заказа. Итог не сохраняется и исчезает после перезагрузки.

Проверка формы не подтверждает существование телефона, email или адреса. Банковские реквизиты не запрашиваются. Сценарий не выполняет отправку формы продавцу.

### Оформление и адаптивность

- Светлая и тёмная темы с сохранением выбора в браузере.
- Локальный SVG-логотип с игрушечным поездом.
- Пять локальных SVG-иллюстраций категорий; одна иллюстрация применяется к нескольким товарам категории, индивидуальных фотографий нет.
- Системные шрифты, отсутствие внешних изображений и библиотек.
- На широком экране общая товарная сетка содержит четыре колонки, каталог с боковыми фильтрами — три.
- При ширине 801–1100 px товарные сетки содержат три колонки, 561–800 px — две, до 560 px включительно — одну.
- До 800 px включительно слева появляется бургер-меню. Навигация и поиск раскрываются под верхней строкой; повторное нажатие или `Escape` закрывает меню.
- На узком экране фильтры каталога сворачиваются в `details`. Начальное состояние выбирается при загрузке; изменение размера уже открытого окна не пересчитывает его автоматически.
- Подписи полей, видимый клавиатурный фокус, ссылка пропуска к основному содержимому, сообщения `aria-live` и связанные с полями ошибки.
- Учитывается системная настройка `prefers-reduced-motion`.

Наличие этих механизмов не означает прохождения полного аудита доступности.

```text
Сайт/

├── product.html

│   ├── css/
│   │   └── style.css         Стили, темы и адаптивные раскладки
│   ├── js/
│   │   ├── data.js           Категории и товары: window.ShopData
│   │   └── script.js         Формирование страниц и клиентская логика
│   └── images/
│       ├── train-logo.svg
│       ├── blocks.svg
│       ├── bear.svg

│       ├── car.svg
│       └── art.svg
```

На каждой странице `data.js` подключён перед `script.js`; оба сценария используют `defer`. Отдельный `app.js` больше не используется.

Чтобы добавить товар, внесите запись в `rows` файла `data.js`. Поля записи: идентификатор, название, категория, цена, минимальный возраст, наличие и количество элементов. Категория определяет общую иллюстрацию, материал и описание. Идентификаторы должны быть уникальными и соответствовать ссылкам `product.html?id=...`.

## Хранение данных и ограничения

В `localStorage` используются два ключа:

| Ключ | Значение |
| --- | --- |
| `igrushechnaya-cart-v1` | JSON-массив объектов `{ id, qty }` |
| `igrushechnaya-theme` | `light` или `dark` |

При восстановлении корзины неизвестные и недоступные товары исключаются, некорректные количества отбрасываются или ограничиваются, повторяющиеся идентификаторы объединяются. Повреждённый JSON заменяется пустой корзиной.

Хранилище привязано к источнику сайта: протоколу, имени хоста и порту. Например, `localhost:8080`, `localhost:8090` и будущий адрес GitHub Pages используют разные корзины. В приватном режиме или после очистки данных браузера сохранённые значения могут исчезнуть.

Если чтение или запись запрещены, показывается уведомление, а текущие изменения остаются в памяти страницы. Сохранение при переходе на другую страницу в таком режиме не гарантируется.

Имя, email, телефон и адрес не записываются в `localStorage` и не отправляются сценарием. Аналитика, cookies и платёжные компоненты не подключены. Ссылки `mailto:` и `tel:` могут открыть внешнее почтовое или телефонное приложение по действию пользователя.

При изменении корзины в другой вкладке открытая форма оформления создаётся заново; её ещё не завершённые поля могут сброситься.

Подробности и оставшиеся сценарии находятся в `TESTING.md`; исторические результаты в этом файле относятся к указанным там этапам разработки. Они не означают, что все последующие изменения прошли тот же автоматизированный прогон.

Полный аудит доступности, проверка экранным диктором, Safari и всех возможных граничных состояний не заявляются.

## Подготовка к передаче

Для локальной передачи сохраните всю папку с её структурой или упакуйте её в ZIP. Перенос только HTML-файлов без `assets` нарушит работу сайта.

Проект пригоден для размещения на статическом хостинге, например GitHub Pages: точка входа — `index.html`, сборка не требуется. Публикация является отдельным действием; локальный сервер не размещает сайт в интернете. В репозиторий сайта не следует добавлять подписанные документы, личные данные и чужие курсовые работы.
